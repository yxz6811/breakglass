**Feature Branch**: `002-vision-result-adapter`

**治理复核（2026-10-06）**：当前依据 [Spec Constitution 2.1.0](../../.specify/memory/constitution.md) 与 [产品 Constitution 2.1.0](../../docs/BreakGlass-constitution.md)。002 仍是默认关闭的包内样例适配，不获单帧上传或真实服务授权；沿用 `CurveResult/createWake`、1500ms 保底及独立 `vision-decision` 计时。PR #63 不改变本切片验收，包内样例与真实识别证据继续分开。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用识别样例在原位看到可调节的抛物线 (Priority: P1)

演示者把识别适配打开后，在扩展自带演示页把视频暂停在目标画面。系统用一份随演示一起打包、已经标明是样例的识别候选，在画面原位置画出抛物线。从出现到退出，用户都能看出这是识别结果，而且是打包样例，不是已经接通的外部识别。拖动、重置和退出与现有抛物线演示一致。

**Why this priority**: 这是识别适配能单独演示的最小价值。没有真实服务时，仍然可以证明合法识别候选会进入同一条交互，并且来源不会被说成预先准备的示例。

**Independent Test**: 临时打开识别适配，使用与当前视频、目标时间和画面尺寸匹配的打包识别样例，断开网络，完成唤醒、改动一个参数、重置和退出。提交用的默认配置保持关闭，本故事不依赖 1.5 秒超时演练。

**Acceptance Scenarios**:

1. **Given** 识别适配已打开，演示视频暂停在目标画面，且打包样例与该视频、时间和画面尺寸匹配并通过检查，**When** 用户唤醒，**Then** 抛物线出现在画面原位置，交互期间持续显示「识别结果」以及「随演示打包的识别样例，尚未接通外部识别。」
2. **Given** 这条识别样例已经进入交互，**When** 用户拖动控制点、重置、按 Esc 或退出，**Then** 参数停在样例允许的范围内，重置回到这次结果的初值并保留交互层，退出后交互层消失且视频保持暂停。
3. **Given** 识别适配保持关闭（提交用的默认配置），**When** 用户按现有演示完成一次唤醒，**Then** 来源仍全程显示「预先准备的示例」，不出现「识别结果」。

---

### User Story 2 - 不合格的识别候选不会变成成功 (Priority: P2)

识别适配打开时，候选可能缺字段、数值无效、对不上当前画面，或给出的可信程度太低。用户应看到可理解的失败，并能重试或退出。匹配的预先准备结果不得被自动画成识别成功。

**Why this priority**: 适配器的价值在于拒绝坏结果。只做成功路径时，非法候选仍可能进入画面。

**Independent Test**: 识别适配打开，分别使用非法样例、与当前画面不一致的样例，以及可信程度低于一半的样例。每种情况都不绘制曲线。不要求外部服务，也不要求四画幅。

**Acceptance Scenarios**:

1. **Given** 识别适配已打开，候选缺少关键数值、数值无效、区域越界、公式不受支持，或与当前视频、时间或画面尺寸不一致，**When** 用户唤醒，**Then** 不绘制曲线，用户看到「外部结果不可用，未进入交互。」，并可重试或退出。
2. **Given** 识别适配已打开，候选给出的可信程度低于一半，**When** 用户唤醒，**Then** 结果被拒绝，不绘制曲线，也不显示编造的准确率。
3. **Given** 候选没有给出可信程度，其余检查都通过，**When** 用户唤醒，**Then** 可以进入交互，界面不显示百分比。
4. **Given** 当前帧存在匹配的预先准备结果，但识别候选不合格，**When** 唤醒失败，**Then** 预先准备结果不得被画成识别成功，也不得自动顶上交互层。

---

### User Story 3 - 识别耗时不混进预制回退，默认演示仍是预制 (Priority: P3)

现场需要分别看到「这次识别判定用了多久」和「超时后预制曲线出现用了多久」。识别适配的计时不得改写现有预制回退口径。提交的演示配置保持识别适配关闭；演练打开后必须能改回关闭。

**Why this priority**: 两条耗时混在一起会让现有 1.5 秒回退验收失真。默认关闭保证未演练识别时，演示与现在一致。

**Independent Test**: 用打开识别适配的一次成功和一次失败记录判定耗时；再用关闭识别适配、沿用现有超时演练的方式确认预制回退记录仍然只覆盖「判定超时到曲线出现」。演练结束后配置恢复为关闭。

**Acceptance Scenarios**:

1. **Given** 识别适配已打开，**When** 一次唤醒进入交互或可恢复失败，**Then** 这次判定耗时被单独记下，且不写入预制回退的那组耗时。
2. **Given** 识别适配关闭，外部结果超过 1.5 秒且存在匹配的准备结果，**When** 发生超时回退，**Then** 用户仍看到超时改用预先准备示例的说明，1.5 秒上限不变。
3. **Given** 演练时曾经打开识别适配，**When** 演练结束，**Then** 随扩展提交的配置恢复为关闭，默认唤醒不再显示「识别结果」。

---

### Edge Cases

- 识别适配关闭时，任何识别样例都不得进入交互，也不得改变现有等待、取消、超时回退和预制来源。
- 识别适配打开的同时，若仍在演练「一直不返回 / 非法外部结果 / 迟到结果」，以该演练为准，识别样例不得再打开一层识别交互。
- 用户取消、退出、开始播放或离开目标时间后，较早的识别候选不得打开或改写当前画面。
- 连续退出再唤醒，或换帧再唤醒，只保留与当前视频和当前时间匹配的结果。
- 候选未标明「随演示打包的识别样例」时必须拒绝，避免把未接通的服务说成已经识别成功。
- 可信程度缺失时不编造百分比；可信程度存在但不是有限数，或低于一半时拒绝。
- 视频打不开或页面不在已验证演示页时，不挂识别曲线，不改写页面。
- 打包样例与正式视频尚未对齐时，不得把样例说成正式素材已经验收。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 识别适配必须有明确开关。随扩展提交的默认配置为关闭。关闭时，用户可见行为与当前预先准备的抛物线演示一致，来源保持「预先准备的示例」。
- **FR-002**: 开关打开且候选合法时，用户必须能在扩展自带演示页的视频原位置看到抛物线，并在交互全程同时看到「识别结果」和「随演示打包的识别样例，尚未接通外部识别。」
- **FR-003**: 合法识别结果必须与当前视频、目标时间、画面尺寸和参数范围匹配。时间单位为秒，目标时间容差为 ±0.2 秒。参数必须满足最小值 ≤ 初值 ≤ 最大值且步长大于 0。画面区域宽高为正且完全落在画面尺寸内。
- **FR-004**: 拖动必须把参数限制在候选给出的范围内。重置恢复这次结果的初值并保留交互层。退出、Esc 和点击交互层以外的区域必须移除交互层并保持视频暂停。
- **FR-005**: 候选缺字段、数值非有限、区域越界、公式不受支持、视频或时间或画面尺寸不匹配、可信程度低于一半，或未标明打包样例时，必须拒绝。用户看到「外部结果不可用，未进入交互。」，并可重试或退出。不得绘制曲线。
- **FR-006**: 不合格的识别候选不得改写为成功。即使当前帧有匹配的预先准备结果，也不得自动把它显示成识别成功。
- **FR-007**: 可信程度可以不提供。未提供时不显示百分比，也不因此拒绝一份其余检查已通过的打包样例。提供时必须是 0 到 1 的有限数；低于 0.5 则拒绝。界面不得编造准确率。
- **FR-008**: 每次唤醒只接受与当前视频和当前时间匹配的结果。取消、退出、播放、离开目标时间、换帧或重复唤醒之后，较早结果不得覆盖当前画面。
- **FR-009**: 外部等待上限仍是 1.5 秒。本功能不得加长该上限。识别适配关闭时，超时后仍自动改用匹配的预先准备结果，并持续显示超时原因。
- **FR-010**: 识别适配打开时，若同时处于「一直不返回」「返回非法结果」或「迟到结果」演练，必须继续该演练，不得改由识别样例进入交互。
- **FR-011**: 识别判定从发起到进入交互或可恢复失败的耗时必须单独记录，不得记入「判定超时到首个可见曲线」这组预制回退耗时。记录只留在当次页面内存中，不含图像、密钥或整段候选原文。
- **FR-012**: 本功能不得要求注册、登录、上传单帧、保存历史，也不得把画面送到浏览器之外。不得加载远程可执行代码，不得放置服务密钥，不得宣称外部识别已经接通。
- **FR-013**: 唤醒不得改写演示页播放控制或替换视频来源，也不得注入未验证网页。没有可播放视频时不得挂曲线。
- **FR-014**: 固定夹具必须先于实现写好：至少一份合法打包识别样例被放行，一份非法样例被拒绝。夹具不含密钥或真实个人信息。

### Key Entities

- **识别适配开关**: 随扩展打包的配置。关闭时走预先准备的演示；打开时才接受标明为打包样例的识别候选。提交配置保持关闭。
- **识别候选**: 一次唤醒使用的抛物线描述。它记录来源、是否为打包样例、可选的可信程度，以及对应的视频、时间和画面区域。只有检查通过且与当前画面匹配的候选可以进入交互。
- **预先准备结果**: 现有演示已经使用的本地结果。它可以被超时回退使用，但不得在识别失败时伪装成识别成功。
- **交互会话**: 用户正在调节的那一层。规则与现有抛物线演示相同：同一时刻只有一层，重置保留该层，退出后视频保持暂停。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 识别适配关闭时，连续 10 次唤醒都显示「预先准备的示例」，0 次显示「识别结果」。
- **SC-002**: 识别适配打开且打包样例合法时，用户从暂停的目标画面开始，可以在 90 秒内完成唤醒、改动一个参数、重置和退出；全程离线，并且每次都能看到「识别结果」和「尚未接通外部识别」。
- **SC-003**: 对缺字段、画面不匹配、可信程度低于一半这三类候选，各演练 1 次，3 次都不绘制曲线，3 次都提供重试或退出，0 次被呈现为识别成功。
- **SC-004**: 识别判定耗时与预制回退耗时分开可查。预制回退仍只统计判定超时到曲线出现，且等待上限仍为 1.5 秒。
- **SC-005**: 演练结束后，提交配置中的识别适配为关闭。默认路径在断网时仍能用预先准备的示例完成现有抛物线演示。

## Assumptions

- 本功能是产品 P1 的第一条切片，只做识别结果适配。Python 执行、单帧上传、外部识别服务、感知代理、任意网站注入和第二条数学曲线都不在本次验收内。
- 规格里的 P1、P2、P3 是本功能内用户故事的顺序，不是产品宪法里的 P0/P1。
- 本切片未获单帧离开浏览器的授权。因此「识别结果」在 002 中只能源自随扩展打包的样例，界面必须写明尚未接通外部识别；003、005 与原则 IX 的独立上传范围不由 002 继承。
- 可信程度门槛采用 0.5：低于该值拒绝；不提供则不显示百分比。该数字是本功能的验收门槛，不是模型准确率。
- 不合格识别候选与现有「外部结果不可用」使用同一句用户可见说明，以便失败路径可操作且不另造一套错误话术。
- 现有抛物线的拖动、重置、退出、1.5 秒回退、±0.2 秒时间和 2% 对齐规则继续有效。本功能不改这几项的验收口径，也不把打包样例写成正式视频已对齐。
- 原实现前置治理修订已由 Spec Constitution 1.4.0 / T002 完成，历史依据保留；当前 2.1.0 继续限制 `visionAdapter: fixture` 与包内样例证据，不据此放行真实上传。
- 演示页没有新增设置面板。开关通过随扩展打包的配置临时打开，演练后改回关闭。
