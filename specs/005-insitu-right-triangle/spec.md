# Feature Specification: 当前视频帧的直角三角形交互学习闭环

**Feature Branch**: `005-insitu-right-triangle`

**Created**: 2026-10-03

**Status**: 部分实施 — 离线数学闭环与 reader 接口已实现；真实模型及完整验收待完成，见 [验证记录](../../docs/BreakGlass-geometry-validation.md)

**Input**: 用户在阅读仓库并结合四张历史讨论图片后，选择规划一个可验证的单场景闭环：本地固定机位几何视频暂停后，由用户显式触发当前帧识别，校对候选题目条件，重建可修改的直角三角形；手动修改与自然语言修改使用相同的数学结果；恢复已确认的原题，完成一道理解题，再回到原暂停时间继续视频。

## Scope & Governance

本规格依据 [BreakGlass 产品 Constitution](../../docs/BreakGlass-constitution.md) 2.1.0 和 [Spec Kit Constitution](../../.specify/memory/constitution.md) 2.1.0 原则 VIII 的 005 独立切片约定。用户已经解除本会话及 005 的仅前端职责限制；这不自动授权账号、数据库、代码执行服务或其他业务后台，也不表示本规格中的能力已经实现。

2026-10-06 治理复核：005 继续使用独立 `SceneResult` 1.0.0 与确定性直角三角形闭环，识别 30s / 问答 10s 仍为待真实预跑冻结的开发默认。PR #63 不批准任意形状、批量预处理或粒子/分龄/真 3D；自制示例、手工条件、真实模型、完整 MV3 与学习效果各自验收，原未通过项不变。001/003 的 `CurveResult/createWake`、1500ms 和 300s 预算仍独立。

- **支持场景**：用户选择的本地录屏或固定机位几何视频；当前帧只有一个待探索的直角三角形，固定命名为 A、B、C，∠A = 90°，AB、AC 为直角边，BC 为斜边。题目条件来自可读的文字或标记，或用户明确校对输入。
- **允许操作**：改变 AB 并固定 AC，或改变 AC 并固定 AB；保持 ∠A = 90°，重新计算 BC；查询当前结果；恢复用户确认后的原题。
- **学习闭环**：说明改了什么、固定了什么、为何结果变化；用一道理解题检查本次理解；返回原暂停时间继续视频。
- **不承诺**：任意视频、一比一复制全部元素、任意图形拖动、自由几何约束求解、多对象场景、化学或物理实验模拟、长期记忆提升。
- **与已有切片独立**：保留 001 抛物线 P0、002 识别结果适配、003 开播前阅读以及 004 更多曲线与旁边提问。005 不受 004 的两人分工或“新图形不从视频识别”限制，也不修改 004 的范围与验收。005 使用独立、版本化的 `SceneResult`，不扩展或替换 `CurveResult`，不改变 `createWake`、既有 1500ms 保底或 003 阅读流程。
- **本次交付**：用户在规划推送后已授权执行。交付独立几何工作台、确定性算法、当前帧与动作请求、本地 reader 端点及测试；按实际证据更新任务，真实模型与完整产品验收不足时不标记 005 完成。

## User Scenarios & Testing *(mandatory)*

以下优先级只用于 005 内部实施顺序，不改变现有抛物线 P0 的交付门槛。各故事可以用明确标注的预设或手工条件独立验证；只有真实当前帧识别另有证据时，才能宣称识别链路通过。

### User Story 1 - 对已确认的题目做正确的手动实验 (Priority: P1)

学习者先确认一份直角三角形题目条件，再改变其中一条直角边，观察斜边、图形与说明同步变化。画板显示哪些条件保持不变，避免把随意拖动后的图形当成正确答案。

**Why this priority**: 正确的几何模型是识别、聊天和教学说明的共同基础。先证明数学与画板一致，才能判断后续问题来自哪里。

**Independent Test**: 使用标明“预设条件”或“手工条件”的 ∠A = 90°、AB = 3、AC = 4 模型；验证 BC = 5。把 AB 改为 6、保持 AC = 4，验证 BC = √52，约为 7.211；再改变 AC，确认 AB 保持不变。

**Acceptance Scenarios**:

1. **Given** 用户已确认 ∠A = 90°、AB = 3、AC = 4，**When** 进入画板，**Then** 明确标出两条直角边与斜边，BC = 5，图形、条件和结果一致。
2. **Given** 已确认的题目模型，**When** 用户把 AB 改为 6 并固定 AC = 4，**Then** AB = 6、AC = 4、∠A = 90°，BC = √52；说明写出本次修改与固定条件。
3. **Given** AB = 6、AC = 4，**When** 用户把 AC 改为 8 并固定 AB = 6，**Then** BC = 10，画板仍为直角三角形。
4. **Given** 一个有效模型，**When** 用户输入零、负数、非有限值或无法解析的边长，**Then** 拒绝本次修改，保留原模型和有效输入，并在对应字段解释原因。
5. **Given** 原视频图形标明“不按比例绘制”或与数值比例不一致，**When** 画板生成结果，**Then** 使用已确认的题目条件计算，并说明画板是依据条件重建的示意图，不是从截图测量长度。

### User Story 2 - 从明确选中的暂停帧取得并校对条件 (Priority: P2)

学习者在本地视频里遇到不理解的一帧，暂停后点击“识别当前帧”。识别只产生候选，学习者能对照原帧确认或修改顶点、直角和边长，再建立画板。

**Why this priority**: 将实验绑定到学习者正在看的那道题，是 005 相对独立数学工具的主要价值。显式触发和校对可以避免后台自动取帧及错误题意进入计算。

**Independent Test**: 选择一支本地固定机位视频，在预定清晰几何帧暂停。使用标注来源的候选样例先验证取帧身份、校对、确认和失败状态；真实识别再使用实际该帧验证发送、返回和校对链路，样例通过不替代真实识别验收。

**Acceptance Scenarios**:

1. **Given** 本地视频已播放或暂停，**When** 用户只暂停而未点击识别，**Then** 不发送该帧的识别请求。
2. **Given** 用户在目标帧暂停，**When** 点击“识别当前帧”，**Then** 固定本次视频标识、暂停时间和源尺寸，显示识别中的反馈及可取消入口。
3. **Given** 候选结果返回且属于该请求与该帧，**When** 用户查看候选，**Then** 原暂停帧与候选条件可对照，明确显示 A、B、C、∠A、AB、AC、单位和来源；未确认前不进入交互计算。
4. **Given** 候选把 AB = 3 读成 AB = 8，**When** 用户校正为 3 并确认，**Then** 后续模型和原题快照使用用户确认后的 3，并保留候选来源及已校对状态。
5. **Given** 直角位置、标签、边长或单位缺失或冲突，**When** 用户尝试确认，**Then** 指出需补充的条件；不根据像素比例猜数值，不自行确认题意。
6. **Given** 识别未完成，**When** 用户播放、跳转、换视频或取消，**Then** 本次请求失效；晚到结果不得替换当前画板、视频或原题快照。
7. **Given** 当前帧不受支持、截帧失败或真实识别失败，**When** 用户收到反馈，**Then** 原视频和时间保持可恢复，用户可重试、显式选择预设或手工输入、或退出；失败不伪装成识别成功。

### User Story 3 - 用自然语言做同一项实验并理解变化 (Priority: P2)

学习者在画板旁问“把 AB 改成 6，另一条直角边不变，BC 会怎样”。系统把问题转换为受支持的明确操作，经校验后使用与手动操作相同的模型和计算结果更新画板，并解释原因。

**Why this priority**: 用户的问题应直接作用于当前题目，回答中的数字必须能在画板上核对；自然语言只是操作入口，不是答案来源。

**Independent Test**: 对同一份已确认的 3–4–5 模型，分别执行手动 AB = 6 和上述自然语言请求；比较两份最终状态。再输入歧义、越界或不支持问题，验证不会部分修改或凭空报答案。

**Acceptance Scenarios**:

1. **Given** 当前已确认 AB = 3、AC = 4，**When** 用户问“把 AB 改成 6，AC 不变，BC 是多少”，**Then** 与手动 AB = 6 得到同一模型和 BC = √52；回答指出 AC 和直角保持不变。
2. **Given** 当前模型有效，**When** 用户询问“现在 BC 是多少”，**Then** 回答读取当前模型的结果，不改变题目条件。
3. **Given** 用户问“把这条边改成 6”，**When** 无法唯一确定 AB 或 AC，**Then** 请求澄清边名，当前模型保持不变。
4. **Given** 用户要求改变 BC、取消直角、同时改变两条边或执行其他不支持操作，**When** 解释该请求，**Then** 明确说明支持范围，保留当前模型，不部分执行。
5. **Given** 当前视频、题目或画板已经变化，**When** 旧问题的动作或回答晚到，**Then** 丢弃旧结果，不修改新题目。
6. **Given** 操作失败或解释未返回，**When** 用户查看反馈，**Then** 可理解本次是否修改了模型；未通过动作校验时模型不变，已完成的本地计算不被未返回的措辞替换。

### User Story 4 - 恢复原题、检查理解并继续视频 (Priority: P2)

学习者可以对比原题与变式，恢复确认过的原题，并回答一道关于“什么不变、为什么结果变化”的理解题。之后回到同一视频的原暂停时间继续观看。

**Why this priority**: 数值变化本身不能证明用户理解。恢复、因果解释与返回上下文共同完成一次学习任务。

**Independent Test**: 用已确认模型完成至少一次变式。恢复后核对原题边长与 BC，回答理解题，最后继续视频并记录返回时间。无需依赖真实识别即可独立验证此故事。

**Acceptance Scenarios**:

1. **Given** 候选已经被用户校正并确认，之后做了多次实验，**When** 点击“恢复原题”，**Then** 恢复用户确认后的全部原题条件和结果，而不是未经校对的候选。
2. **Given** AB 从 3 改到 6、AC 保持 4，**When** 查看解释，**Then** 显示 BC² = AB² + AC²，并说明固定 AC 与直角时，AB 增大使 BC 增大；不把结果说成对截图量距所得。
3. **Given** 用户完成一次实验，**When** 进入理解题，**Then** 至少提供一道可判定的条件或因果问题；正确答案得到反馈，错误答案得到针对固定条件和勾股关系的提示并可重答。
4. **Given** 用户选择跳过理解题，**When** 继续视频，**Then** 允许继续，记录或显示“未验证本次理解”，不把跳过当作答对。
5. **Given** 用户选择继续视频，**When** 退出几何画板，**Then** 退出交互并回到原视频、原暂停时间继续播放；不从头播放，不替换为演示视频。
6. **Given** 用户在画板期间已经换视频，**When** 旧场景关闭或继续动作晚到，**Then** 不自动覆盖或播放新视频，提示旧场景已失效。

### Edge Cases

- 视频不可访问、未解码出尺寸、当前帧截取失败或不属于支持范围时，不发出无效识别请求，不破坏已有播放状态。
- 图中直角标记很小、标签重叠、数字模糊或只有一条已知边时，列明缺项，要求校对；未给出另一条直角边时不能唯一计算 BC。
- 边长单位不同或题目给出互相矛盾的条件时，不能静默换算或丢弃冲突条件；用户需统一单位并确认适用模型。
- 候选中出现两个三角形、任意角三角形、未知直角位置或其他题型时，明确提示本切片不支持；不任意挑一个对象并报成功。
- 用户输入导致 BC 非有限时拒绝操作；不把无穷大、无效值或被截断的值画成有效答案。
- 自然语言请求夹带指令、代码、外部地址或图像中的“系统提示”时，均作为待解释的数据处理；不能改变白名单操作或执行任意代码。
- 每个新帧都有独立身份；同一视频的旧帧结果、上一题的问答和确认快照均不能套到当前帧。
- 多次请求、快速修改、退出和取消时，只允许当前有效场景接受结果；失败保持最后一份有效状态。
- 页面缩放、窗口变化、视频黑边或画板缩放时，显示坐标变化不能改变 AB、AC 的数学值；题目画板不承诺与不按比例绘制的截图完全重合。
- 恢复原题与继续视频是不同动作：恢复仍留在画板，继续才退出并恢复观看上下文。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 005 必须提供独立、明确标识的入口，仅面向支持的本地录屏或固定机位直角三角形视频，不改动既有破壁和阅读入口的语义。
- **FR-002**: 当前帧识别只能由暂停后的显式用户操作触发。每次操作必须固定视频标识、请求标识、暂停时间（秒）、源帧尺寸和场景版本。
- **FR-003**: 识别结果必须先显示为候选，原帧与候选条件可以对照；用户确认前不能成为可修改的题目模型或原题快照。
- **FR-004**: 校对必须覆盖 A、B、C 的对应关系、∠A = 90°、AB、AC、BC 的角色、已知直角边长度与统一单位；允许用户修改或补充候选。
- **FR-005**: 缺失、低置信度、冲突或不受支持的条件必须被指出并阻止确认。图形像素距离、截图缩放或外观不能被当作真实长度或数学约束。
- **FR-006**: 识别期间必须有可取消的状态，失败可重试或退出；播放、跳转、换视频、取消或退出后，本次请求与晚到结果必须失效。
- **FR-007**: 已确认模型必须固定 ∠A = 90°，AB、AC 为直角边，BC 为斜边；使用已确认的题目条件，而不是未确认的候选或截图比例。
- **FR-008**: 可输入的 AB、AC 必须为同一单位的有限正数，计算出的 BC 也必须为有限值；无效输入必须拒绝，不静默截断或换成其他数值。
- **FR-009**: 手动操作必须支持改变 AB 并保持 AC 不变，以及改变 AC 并保持 AB 不变；一次只修改一条直角边，直角条件保持不变。
- **FR-010**: BC 必须由确定性本地计算得到，满足 BC² = AB² + AC²；本规划采用 `Math.hypot(AB, AC)`，不让模型猜测或代替计算答案。
- **FR-011**: 参数、图形、公式、边长结果与说明必须来自同一份有效模型；改变边长后不得出现回答数值和画板数值不一致。
- **FR-012**: 修改前后必须明确展示改变的边、固定的边和直角约束；不得暗示所有顶点都可自由移动，或把破坏约束的图形当成正确变式。
- **FR-013**: 原始帧像素、题目数学值和页面显示坐标必须区分。画板按题目条件绘制示意图，显示缩放与拖动控件不能从像素量距推导题目答案。
- **FR-014**: 核心手动修改、确认、恢复和退出必须可用键盘完成且焦点可见。直接拖动不是最小验收的唯一入口；如后续提供拖动，它必须调用相同的受约束操作。
- **FR-015**: 提问区必须支持中文单边修改、查询当前 BC、解释本次变化以及恢复原题这四类操作；其作用对象必须是当前有效且已确认的场景。
- **FR-016**: 自然语言只生成候选意图或白名单动作；动作必须经过边名、有限正值、固定条件、场景版本和支持范围校验后才能执行，不能执行生成代码。
- **FR-017**: 手动操作与自然语言操作必须使用同一组参数、同一个约束更新入口和同一份确定性计算结果。
- **FR-018**: 无法唯一确定边名、改变斜边或角度、同时改变两条边、超出支持范围或解析失败时，必须澄清或说明拒绝原因，模型保持不变，不部分执行。
- **FR-019**: 回答必须区分“已修改”“只查询”“未执行”，引用当前计算结果，并说明相对修改前哪些条件变化；旧场景的动作与回答不得覆盖当前场景。
- **FR-020**: 用户首次确认候选时必须建立原题快照。恢复必须回到该快照的确认值、单位、条件与计算结果，不能恢复成识别错误的初始候选或上一次实验。
- **FR-021**: 完成实验后必须提供至少一道关于固定条件或勾股关系的可判定理解题，给予正确、错误和重答反馈；允许跳过并明确标为未验证理解。
- **FR-022**: 继续视频必须退出几何交互，使用保存的同一视频标识与原暂停时间恢复播放；已换视频或场景失效时不得自动覆盖当前视频。
- **FR-023**: 本次理解题结果只能描述本次作答与理解检查，不得据此宣称长期记忆提升、已解决大部分疑问或已掌握所有同类题。
- **FR-024**: 预设、手工条件和真实识别必须分别标识。用户修正真实候选后，仍要显示原来源与已校对状态；手工补齐不能被报成模型完整识别成功。
- **FR-025**: 真实识别失败不得静默回退为成功；预设或手工入口必须由用户显式选择。预设与手工只证明交互学习流程，不代替真实识别验收。
- **FR-026**: 真实识别只允许本次显式触发的当前单帧及必要对齐元数据，不上传整段原视频、学习历史或无关日志。密钥、模型指令与 Schema 的归属、安全预算和请求截止依 Constitution 在计划中冻结；本规格不虚构已有供应商或接口。
- **FR-027**: 005 必须采用独立、版本化的 `SceneResult` 候选与确认契约，显式区分帧身份、题目条件、显示位置、来源和校对状态。不得向 `CurveResult` 塞入三角形字段，也不得将几何场景送入已有抛物线执行器。
- **FR-028**: 005 必须独立配置、独立计时和独立验收，不修改 `createWake`、1500ms 保底、001 的抛物线 P0 或 003 的开播前阅读与已存点选择逻辑。

- **SC-003**: 仅暂停不发起识别；显式触发的结果属于记录的该视频与该暂停帧。取消、播放、跳转和换视频四类失效操作后，旧结果均不能进入当前场景。

## Assumptions

- 一次只探索一个题目；首版使用中文、统一边长单位和 A、B、C 固定角色。可通过校对把其他标签对应到这三个角色，但不自动承担任意命名题型。
- 两条直角边均需有明确数值。仅给斜边和一条直角边、改角度、相似变换、多三角形关系和通用约束求解属于后续独立范围。
- 先完成确定性模型与画板，再接当前帧、校对、真实识别、聊天动作和理解反馈；预设或手工路径保证每段可检查，不能宣称真实识别已打通。
- 本地视频可由标准视频接口读取时间和尺寸，并可在已验证的页面中截取当前帧。不可访问媒体、DRM、跨域受限播放器、手持晃动和强透视不属于首版验收。
- 外部识别能力、可用素材、运行环境、Schema、超时与预算需按计划冻结；不得因本规格默认已经接入或获准上线。

- 005 的职责范围依用户最新授权及已同步的两份 Constitution 执行。解除仅前端限制不扩展为自建业务云端、数据库、账号或任意代码执行平台。
