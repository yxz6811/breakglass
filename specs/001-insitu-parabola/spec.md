## User Scenarios & Testing *(mandatory)*

### User Story 1 - 把画面里的抛物线变成能调节的对象 (Priority: P1)

自学的学生或现场演示者正在看一段固定机位的网课或录屏。视频里的抛物线只是画面，不能改参数。用户把视频暂停在指定画面，在原位置唤醒这条曲线，拖动控制点观察变化，再恢复初始形状并退出。整个过程留在扩展自带的演示页上，不把视频分成两块屏幕，也不跳到未验证的网页。

**Why this priority**: 这是产品要让人看见的学习价值，也是当前唯一的交付门槛。只做这一条，就已经能用预先准备的素材完成演示。

**Independent Test**: 只使用团队提供的演示视频和配套曲线，在扩展自带演示页上、不依赖网络识别的情况下，完成暂停、唤醒、调参、重置和退出。正式视频尚未提供时，工程夹具只能证明交互状态，不能记成这条故事已通过。

**Acceptance Scenarios**:

1. **Given** 演示视频已打开并停在目标帧，**When** 用户使用可见入口或快捷键 Alt+B 唤醒，**Then** 一条与画面中抛物线对齐的曲线出现在原位置，并且从出现到退出都标明这是预先准备的示例。
2. **Given** 交互已经出现，**When** 用户拖动曲线上的控制点，**Then** 对应参数的数字和曲线一起变化，参数不会超出素材允许的范围。
3. **Given** 用户已经改动参数，**When** 用户重置，**Then** 参数回到这次结果的初始值，交互层仍然留在画面上。
4. **Given** 交互已经出现，**When** 用户按 Esc、选择退出，或点击交互层以外的区域，**Then** 交互层消失，视频保持暂停，演示页里的播放器可以继续使用。
5. **Given** 视频正在播放或尚未停在目标帧，**When** 用户试图唤醒，**Then** 入口不可用，或先进入可唤醒的暂停状态后才出现曲线；运动中的画面上不会留下一条对不上的曲线。

---

### User Story 2 - 等待失败时仍然诚实、可恢复 (Priority: P2)

演示现场的网络可能很慢或不可用。用户发起一次需要等待外部结果的唤醒时，如果结果来得太慢、结果不可用，或用户中途放弃，画面要保持可操作。预先准备的示例可以接上演示，但必须让人看得出这不是识别成功。

**Why this priority**: 没有这条，故事 1 的演示会在网络波动时停住，或把准备好的示例说成刚刚识别成功。它不替代故事 1，但当前交付必须包括它。

**Independent Test**: 分别演练三种情况：外部结果超过 1.5 秒、当前帧没有可用的准备结果、用户在等待中取消。每种情况都不需要先完成真实识别。

**Acceptance Scenarios**:

1. **Given** 当前视频和时间有匹配的准备结果，且外部结果超过 1.5 秒还没到来，**When** 等待到达 1.5 秒，**Then** 用户不用再次点击就能看到准备好的曲线，并持续看到“因超时改用预先准备的示例”及原因。此后才到来的外部结果不得改变这条曲线。
2. **Given** 当前帧没有匹配的准备结果，**When** 等待失败或超时，**Then** 用户看到可理解的失败说明，可以重试或退出，界面不得显示为成功。
3. **Given** 用户正在等待，**When** 用户取消，**Then** 等待状态消失并回到暂停画面；之后到来的结果不得再打开交互层。
4. **Given** 用户已经完成一次唤醒，**When** 用户退出后再次唤醒，或换到另一帧再唤醒，**Then** 只有与当前视频和当前时间匹配的结果留在画面上。

---

### User Story 3 - 换画幅后曲线仍然贴住原图 (Priority: P3)

同一条抛物线会在不同窗口比例和黑边下观看。用户改变窗口后，交互曲线仍应落在视频内容里的那条抛物线上，而不是落在黑边或整块播放器外框上。

**Why this priority**: 原位对齐是“这就是视频里的那条线”的证据。故事 1 可以先在一种固定画幅下成立；正式验收要覆盖多种画幅。

**Independent Test**: 使用同一目标帧，在 16:9、4:3、竖屏和带黑边四种条件下唤醒，并在交互出现后改变一次窗口大小。

**Acceptance Scenarios**:

1. **Given** 同一目标帧和同一套曲线定义，**When** 用户分别在 16:9、4:3、竖屏和带黑边的画面中唤醒，**Then** 曲线与视频内容中的抛物线之间的偏差不超过视频内容区域较短边的 2%。
2. **Given** 交互已经显示，**When** 用户改变窗口大小，**Then** 曲线重新贴合，偏差仍不超过该上限。
3. **Given** 页面上没有可访问的视频，或页面不在已验证的范围内，**When** 用户尝试唤醒，**Then** 原页面的播放器不被改写，入口保持不可用或出现明确的不可用说明。

---

### Edge Cases

- 用户连续快速唤醒时，不得叠出多层互相覆盖的曲线；进行中的一次等待结束前，新的唤醒不得把旧结果留在画面上。
- 交互已经打开时，如果视频开始播放或离开目标帧，曲线不得继续盖在旧画面上。
- 用户把控制点拖到允许范围的边界时，参数停在边界内，不得画出素材不允许的形状。
- 准备结果与当前视频、目标时间或画面区域不一致时，不得把它当成当前帧的成功结果。
- 外部结果缺少关键数值、数值无效，或对不上当前帧时，按失败处理，并给出重试或退出。
- 没有准备结果、视频打不开、用户取消，这三种情况都要留下下一步，不得只留下一块无法关闭的等待提示。
- 正式演示中，预先准备的结果在任何时刻都不得被说成识别成功。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 用户必须能播放、暂停团队提供的演示视频，并定位到指定的目标帧。
- **FR-002**: 破壁入口只在视频暂停于可唤醒的目标帧时可用。其他状态下入口不可用，或先进入该状态后再出现曲线。
- **FR-003**: 用户必须能在扩展自带演示页的视频画面原位置唤醒抛物线。唤醒不得把画面分成独立的两屏，也不得离开该演示页。从扩展图标进入演示页是打开产品，不是一次唤醒。
- **FR-004**: 曲线的公式、初始参数、每个参数的允许范围和步长、画面中的区域，以及数学坐标的范围和方向，必须来自与该视频和目标帧配套的演示素材。
- **FR-005**: 用户必须能拖动曲线上的控制点改变至少一个参数，并立刻看到数字、控件和曲线一起变化。参数必须限制在素材给出的范围内。
- **FR-006**: 重置必须恢复这次结果的初始参数，并保留交互层。
- **FR-007**: 退出必须移除交互层，使播放器回到可以继续操作的原页面状态，并保持视频暂停。Esc、明确的退出操作，以及点击交互层以外的区域，都必须能退出。
- **FR-008**: 交互从出现到退出必须持续显示数据来源。本功能验收所使用的准备结果必须标为预先准备的示例，不得标为识别成功。
- **FR-009**: 当一次唤醒需要等待外部结果时，超过 1.5 秒必须自动改用与当前视频、目标时间和画面区域匹配的准备结果，无需用户再次点击，并持续显示超时回退的原因。更晚到达的外部结果必须丢弃。
- **FR-010**: 外部结果不可用、结果与当前帧不匹配，或没有可用的准备结果时，系统必须给出可理解的说明，并提供重试或退出。这些情况不得显示为成功。
- **FR-011**: 用户必须能在等待过程中取消。取消后回到暂停画面，随后到达的结果不得打开交互层。
- **FR-012**: 每次唤醒只接受与当前视频和当前时间匹配的结果。重复唤醒、切换帧或退出之后，较早的结果不得覆盖当前画面。
- **FR-013**: 视频开始播放或离开目标帧时，系统必须撤下仍绑定在旧帧上的交互曲线。
- **FR-014**: 在 16:9、4:3、竖屏和带黑边四种条件下，以及窗口大小变化之后，曲线与视频内容中抛物线的偏差不得超过视频内容区域较短边的 2%。位置以视频画面本身为准，不得只按播放器外框计算。
- **FR-015**: 系统不得要求用户注册、登录、保存历史或把修改后的视频上传到云端。
- **FR-016**: 唤醒不得改写演示页的播放控制，也不得替换视频来源。退出后播放器必须仍能按演示页上的控件继续使用。本功能不得注入未验证的网页。
- **FR-017**: 键盘用户必须能看见当前焦点，并用 Esc 完成退出。
- **FR-018**: 演示页没有可播放的视频，或页面不在已验证范围内时，系统不得挂上曲线，也不得改写该页面。入口保持不可用，或说明为什么不能使用。
- **FR-019**: 准备结果必须与指定视频、目标时间、画面区域和参数范围一致。正式演示不得在未标明来源时把准备结果呈现为识别成功。
- **FR-020**: 在网络不可用时，用户仍必须能用准备好的演示视频和配套曲线完成故事 1。

### Key Entities

- **演示视频**: 团队提供的一段录屏或固定机位课件，包含可定位的目标时间。它是本功能唯一承诺能唤醒的素材。
- **抛物线定义**: 与某个视频和目标时间配套的公式、初始参数、参数范围和步长、画面区域，以及数学坐标的范围和方向。
- **破壁结果**: 一次唤醒所使用的抛物线定义。它记录来源是预先准备还是外部识别、是否因为超时而改用准备结果，以及它对应的视频和时间。只有来源、视频和时间都匹配当前画面的结果可以进入交互。
- **交互会话**: 用户正在调节的那一层。它保存当前参数，允许重置回本次结果的初值，并在退出、取消、播放或离开目标帧时结束。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在已经准备好的演示素材上，用户从暂停的目标帧开始，可以在 90 秒内完成唤醒、改动一个参数、重置和退出，且全程不需要网络。
- **SC-002**: 评审连续观察 10 次使用准备结果的唤醒，10 次都能在交互期间看到“预先准备”或同等含义，0 次被呈现为识别成功。
- **SC-003**: 当外部结果超过 1.5 秒未到来且存在匹配的准备结果时，用户无需再次点击，就能在超时后 0.1 秒内看到该曲线和超时原因。这 0.1 秒只计算从判定超时到曲线出现，不包括打开产品、等待视频第一帧，或任何后续增强能力的首次加载。
- **SC-004**: 在 16:9、4:3、竖屏、带黑边，以及一次窗口大小变化后，曲线与视频内容中抛物线的偏差都不超过内容区域较短边的 2%。
- **SC-005**: 对“没有准备结果”“用户取消”“页面没有可访问视频”三种情况，用户都能在两步操作内回到可继续使用的暂停画面，或看到明确的不可用说明。演示页播放器在这三种情况下都保持可操作。
- **SC-006**: 连续 5 次“退出后再次唤醒”或“换帧后再唤醒”，后一次画面都不被前一次结果覆盖。

## Assumptions

- 规格里的 P1、P2、P3 是用户故事的实现顺序。仓库前端执行基线 `docs/BreakGlass-constitution.md` v1.1.0 规定的当前交付门槛覆盖本规格的全部验收场景，不只是故事 1；`.specify/memory/constitution.md` v1.2.0 是 Spec Kit 治理记忆，其中的感知代理窄例外不属于本仓库交付范围（T019）。
- 当前 README 已改成离线抛物线演示的项目说明，不再包含冲突标记、代码场景或三次方程。README 与已批准的产品宪法冲突时，以宪法的交付边界为准。
- 本功能只验收一条抛物线，并且只在扩展自带的已验证演示页上验收。代码执行、三次曲线、第二个物理演示、任意网页注入和通用识别都不在本次验收内。从扩展图标打开演示页是进入产品，不是唤醒。
- 真实识别，以及把单帧送到外部服务，都还没有获准作为本功能的验收条件。本功能必须在准备结果路径上独立成立。FR-009 到 FR-011 只规定“一旦需要等待外部结果”时的用户可见行为，不要求本次就把识别做成交付物。
- 抛物线的具体公式、初值、范围和步长以最终演示素材为准。本规格不把某一条代数式写成唯一公式。素材未到位前，不得用占位数字宣称已经对准了某段真实视频。
- 重置保留交互层，退出后视频保持暂停。这是为了让“重置”和“退出”成为两个可分别验收的动作。旧版说明里退出后恢复播放的写法不作为本次验收标准。
- 唤醒同时提供可见入口和快捷键 Alt+B。空格不作为唤醒键，避免和播放器的暂停冲突。
- 2% 的位置上限是在团队尚未写下绝对像素误差时采用的验收标准。团队若在计划阶段冻结另一个上限，应以冻结值为准，并同步改 SC-004。
- 玻璃破裂声效、粒子和荧光边框可以增强现场效果，但不是本功能的验收条件。用户必须能从曲线出现、来源说明和可拖动这三个结果判断唤醒已经发生。
- 首版不自动判断一段陌生视频是不是固定机位。验收只使用已验证页面上的指定演示视频。
- 依赖团队在验收前提供：演示视频、目标时间、抛物线定义、画面区域，以及与该帧匹配的准备结果。缺少这些素材时，故事 1 和故事 3 无法判为通过。
