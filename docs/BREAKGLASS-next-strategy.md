## 第一部分　现状总结

### 1.1 项目当前是什么

当前产品运行在 Chrome MV3 扩展自带演示页中，使用 Vanilla JS、CSS 和 SVG。用户可以播放包内示例或自行选择本地视频；曲线流程与 005 直角三角形工作台各有入口和契约。真实识别通过本地无状态 Node reader 调用配置的模型供应商。另有独立静态展示站，展示站的视觉能力不能计入扩展产品验收。

以下事实限定于本次核对提交：

1. `extension/manifest.json` 没有 `content_scripts` 或 `web_accessible_resources`，`permissions` 与 `host_permissions` 都为空。`extension/src/page/` 是扩展自己的页面脚本。**任意真实网站上的视频注入与叠加尚未实现。** 宪法对标准 Video API、独立 overlay 和页面支持范围的约束仍适用于未来获准的注入方案。
2. 页面模块主要通过 `window.BreakGlass.*` 协作，reader 对接通过本地 HTTP。在已核对的产品调用路径中，没有依赖扩展消息协议的跨页面链路；无需用整个仓库中字符串出现次数证明这一点，也不把「无消息」视为禁止将来采用标准 MV3 消息 API 的永久规则。
3. 当前扩展产品的数学绘制使用 SVG。展示站已有 WebGL/Three.js 背景，但它与产品的依赖、性能及验收范围分别管理。P0 默认原生 CSS/SVG；宪法没有把「所有路径永久零依赖」设为绝对规则。

## 第二部分　需要改变的问题

### 2.1 先让愿景对应证据

新增方向扩大了识别、结构化理解、几何校验与呈现的组合范围。任何一层的失败都会影响用户闭环，但仓库没有支持「四层各 50%、整体 6%」这类概率假设的数据。

建议先整理一张可追问的能力表：每项写明输入素材、允许形状、自动/手工路径、失败模式、运行环境和验收记录。优先补已批准切片的证据，再据此选择下一项增强；现有范围内的修复与验证可直接推进，不需要把每个小改动变成新的审批流程。

### 2.2 用交付目标排序，再估算排期

交付日期、人员、正式素材、模型额度和可支持的输入范围都会影响排序。日期未定不妨碍先核对源码和补已有验收；工期应在试验和任务拆分后估算，不能从建议书中的行数、依赖大小或相对量级推导保证。

### 2.3 把演示页、本地视频与真实网站承诺写清楚

当前可交付边界是扩展自带页面中的视频流程。使用用户本地视频与在第三方网站挂载 overlay 可以是不同阶段，不能把其中一个的演示当作另一个已实现。

若要支持真实网站，应先定义目标域名、页面结构、视频可访问性、权限、注入生命周期及退出清理，再选择 MV3 注入和消息方式。`content_scripts`、动态注入、权限申请等是实施选项，不能预先断言只有一种 manifest 组合能实现。跨域 iframe、Shadow DOM、DRM 等按实际支持范围验证。

### 2.4 为 2% 对齐准备独立实测参照

`alignment.js` 的接口是：

```js
sampleAlignment({ definition, parameters, scale, contentRect, samples = 9, readActual })
```

`readActual(mathX)` 可提供独立实测的 CSS 像素坐标，须与期望点使用相同基准（相对视频内容矩形左上角）；缺少回调时，算法默认用计算的期望点自身作比较。`main.js` 的 `publishAlignment` 因此只发布布局读数，并主动保持 `measured: false`、`maxRatio: null`、`withinTolerance: null`，避免把绘制输入与自身比较当成视频对齐证据。

缺口是**独立采集、坐标统一和证据存储的协议**，不必强制新增产品输入框。可评估：

| 方案 | 做法 | 必须保证 |
| --- | --- | --- |
| 验收专用钩子 | 用受控测试入口提交独立量点，再调用偏差算法 | 标明量点来源，不复用刚绘制的路径作为参照 |
| 离线测量脚本 | 冻结帧截图，独立采点或像素分析，计算同一短边归一化偏差 | 记录视频/时间、素材哈希、viewport、DPR、区域和坐标变换 |
| 人工量点协议 | quickstart 明确采点、容差与复核方法，存原图和原始数值 | 可追溯、可重做，并按切片要求补页面测量字段或引用记录 |

对应关系必须精确：**001 SC-004 与 003 SC-005 是 2% 对齐**；003 SC-003 是「下一个」的时间及禁用状态记录，003 SC-004 是第一处耗时与至少 20 次热缓存破壁耗时。后两项不能归因于缺少 `readActual`，应各自补采样与记录。即使采用离线方案，也须满足 003 当前规格对破壁后的测量字段和记录入口要求。

### 2.5 建立可复现的当前验证入口

不同历史提交的测试项数不能互相替代。保留历史报告，每项能力指定一份当前验证入口，至少写明：

- 被测完整 commit；有未提交改动时附差异说明；执行日期与原始日志。
- 实际命令、工作目录、退出码和通过/失败/取消/跳过/未执行结果。
- Node 版本、操作系统；媒体分支所用 ffmpeg 版本、来源及当前进程 PATH 是否可用。
- 测试范围：静态检查、Node 替身、预设/手工、真实模型、确定版本 Chrome 中 MV3、像素和学习效果分别报告。
- 浏览器操作的版本、设备、viewport/DPR、缓存状态、素材与指标起止事件。

仓库现有 `node scripts/check.mjs` 与根目录 `node --test` 可作为复现入口；全量媒体测试需要 ffmpeg。命令跑过只有绑定上述信息才形成基线。构建通过、测试数量增长或 `/health` 配置成功，都不能替代真实模型与像素验收。

### 2.6 拆分页面须说明具体收益

`main.js` 同时接线曲线、预读、当前帧、工具栏与呈现状态，后续维护需要关注耦合。`AGENTS.md` 禁止的是无关大范围重构，并未禁止有明确收益的拆分。

可先评估启动时必需模块与元素的检查，让缺脚本或资源时有可理解的错误；缺失依赖目前可能抛异常或中断初始化，不应一概描述为「静默失效」。拆分时保持 `createWake`、时钟、来源与取消的唯一契约，再按实际风险安排回归。

### 2.7 reader 的边界与待修复项

本地 reader 的 `/read`、`/geometry/read`、`/geometry/ask` 已分别获既有切片授权。端点数量本身不证明它已成长为违宪业务后端；账号与必要历史记录已按原则 XI 纳入新规划，不归既有 reader；云端代码执行仍不在范围。

| 观察 | 准确含义与后续建议 |
| --- | --- |
| 共享扩展校验器 | `page-rules.mjs` 从扩展目录加载阅读规则，几何模块也共享校验。部署须包含对应目录或明确共享包边界；这是校验一致性的选择，不能直接说「无法部署」 |
| `/read` 点内 `source: preset`、`equationId: fixture.parabola` | 是既有缓存与抛物线求值通道，外层同时带 `origin: external`。须保留并校验外层来源、请求/视频/时间绑定和 UI 来源；不能仅看点内字段就判定真实候选与包内示例不可分 |
| 缺少 Origin 时放行 | CORS 限制带 Origin 的浏览器请求，不是服务端身份认证。应明确是否允许本机非浏览器客户端，核对缺 Origin、恶意 Origin 及调用用途；现行为不能当作强访问控制 |
| `READER_HOST` 可覆盖默认 loopback | 默认 `127.0.0.1`，但没有冻结只允许回环地址。为本地服务核对配置限制、暴露范围与失败提示 |
| `/read` 超限后直接 `destroy()` | 可能让客户端得到网络重置而非可读 413；几何端点已有先完成响应再断开的分支，可评估统一传输语义 |
| 预读默认预算 | `READER_BUDGET_MS=240000`，单调用默认 60000ms、并发默认 2。8 帧全占满预算时仅模型等待就可达 240s，尚需请求、定位和校验余量；这是假设最坏情形计算，不是已测耗时 |

错误码可建立映射与记录规则；已有契约内的错误码不能未经修订统一改名。上游请求取消、安全修复及共享校验必须保留当前切片语义。

## 第三部分　候选方向的分层技术草案

### 3.1 L1/L2/L3 与依赖

| 层 | 内容 | 真正前置 | 状态 |
| --- | --- | --- | --- |
| L1 形状与概念泛化 | 版本化类型、参数域、校验、采样与交互 | 确定支持的形状及来源范围 | 候选方向，未获实施批准 |
| L2 预处理时间轴 | 抽帧、去重、分批、候选概念、校验、合并 | 已冻结的输出契约；首版可以仅限现有抛物线 | 新架构草案，未获批量额度或端点批准 |
| L3 表示与解析 | 粒子呈现、解释深度 | 对应的已确认数学对象和确定性结果 | 各自独立决策、开关与验收 |

L3 不必等 L2：可以先在已确认的预设/手工几何上试验呈现与模板解释，并如实注明来源。L2 若仅支持抛物线，也不必等「全几何」完成。只有扩大形状识别范围时，才需要相应的 L1 契约和识别证据。

### 3.2 预处理提前等待，不删除原路径

| 现有路径 | 保持的预算与边界 |
| --- | --- |
| 001 原唤醒 | `fallbackAfterMs: 1500`，匹配缓存保底与迟到丢弃 |
| 当前帧曲线 | 显式提交一张宽不超过 640 的 JPEG，JPEG 与客户端整个请求均限 4MiB，开发默认截止 30s；复用的 `/read` 服务路由仍有 10MiB 统一上限 |
| 003 预读 | 至多 8 张稀疏关键帧，页面 300s 截止；reader 默认 240s |
| 005 几何 | 单次请求 4MiB，识别 30s、问答 10s 开发默认，预跑后冻结 |
| 所有现有路径 | 不上传整段原视频，不因新建议扩大载荷或上传权限 |

预处理可以把模型等待移到观看前，缓存展示仍需要身份、尺寸、来源、取消与可见呈现检查。`createWake` 是同一个工厂，`start` 与 `startCached` 是受控方法，不是两套并存的状态契约。新模式不能自动删除它们，也不能把现有 1500ms、30s、300s 合并成一个处理总时长。

003 的稀疏采样和校验缓存可提供经验，但整段概念分段会改变采样量、成本、隐私与输出语义。若决定实施，先按原则 X 写清新范围；若要删除或重定义旧原则，按 Governance 判断是否需要 MAJOR。

### 3.3 L1：形状注册表与概念类型

注册表可包含 `kind/version/parameterSpec/validate/formula/controlPoint/samplePolylines`，函数图像可以提供 `evaluate(params, x)`，圆等参数曲线提供 `pointAt(params, t)` 或多支读数。不要把所有几何强制建模成单值 `y=f(x)`。

```js
// 接口草案，不是现有 JSON 契约；函数只存在于受控本地实现中。
ShapeRegistryEntry = {
  kind, version, parameterSpec,
  validate,              // 检查形状、有限值及整个允许参数域
  samplePolylines,       // 返回已裁剪的多段数学点
  formula, controlPoint
}
```

`figures.js` 可复用四图形参数检查、圆的多支读数/参数采样、关键点补采样、Liang–Barsky 裁剪和 `MAX_SAMPLES=4097` 上限。实际复用量要在提取后确认，不使用「60–70%」或「80% 是重构」作为依据。

建议按函数图像、圆锥曲线、平面几何、代数推导、概念说明分层。当前 005 的 `SceneResult` **只覆盖直角三角形**，不是整个平面几何类别。代数推导和无图形概念需要额外语义与内容验证，可后置。

每个支持类型需要版本化 Schema、有限参数域、确定性计算/采样、交互规则、失败语义和独立样例。模型只产候选；新增本地图形不等于新增识别能力。

### 3.4 L2：预处理管线

候选流程：本地抽帧 → 去重 → 分批 → 模型候选概念 → 每类确定性校验 → 跨批去重与冲突处理 → `VideoTimeline`。采样、模型输出与合并结果分别可追溯，失败批次和未知区间必须显式保留。

以 10 分钟视频、每张 JPEG **假设** 40KB、每批 8 帧为例：

| 采样间隔 | 估算帧数 | 原始 JPEG 字节量 | 向上取整批次数 |
| --- | --- | --- | --- |
| 1s | 600 | 24MB | 75 |
| 2s | 300 | 12MB | 38 |
| 5s | 120 | 4.8MB | 15 |

这只是容量算术，未计 base64/JSON 开销、边界采样、去重、重试和供应商计费。2s 可作为研究起点，**不能保证不丢信息**；去重收益需真实片段测量，不能承诺减少 30–50% 调用。应包含短暂出现图形、板书切换和遮挡样例。

| 决策 | 候选起点与依据 |
| --- | --- |
| 计算位置 | 浏览器负责本地采样，既有 reader 托管密钥、指令和候选校验。浏览器本地模型是另一个可行但未授权/未验证的选项，不能称为「不可能」 |
| 素材范围 | 先评估用户有权使用的本地文件或团队自制素材，明确将抽取帧交给供应商；本地文件并不自动证明权利或数据纯本地 |
| 在线视频 | 需要访问能力、用户授权、平台规则、素材权利及供应商保留政策的具体评估；没有证据支持统一违法结论或工程量三倍 |
| 每批帧数 | 8–16 只是候选值，须冻结帧数、载荷和供应商限制；当前 003 仍最多 8 帧 |
| 并发 | 不因非实时就默认升至 4–6。依据限流、模型额度、内存、取消及真实吞吐决定 |
| 重试 | 若要有限重试，先定义可重试错误、上限、幂等与额外费用；原切片不得被隐式改变 |
| 处理预算 | 可研究独立分钟级任务预算，不能替换原路径预算。原 `READER_BUDGET_MS=240s` 只描述当前服务默认 |
| 成本 | 触发前展示估算依据、费用上限和不确定项；无供应商价格或模型成本证据时不显示确定金额 |

取消须传到 reader 与上游，已失败/已取消批次不能混入成功片段。若允许部分成功，产物和 UI 都须表达不可用时间段，不把缺口平滑成已理解内容。

### 3.5 `VideoTimeline` 与端点草案

`VideoTimeline` 建议单独版本化，不直接塞入一次破壁的 `CurveResult`。可记录：

```json
{
  "schemaVersion": "DRAFT",
  "videoId": "local-video-7",
  "duration": 612.4,
  "frameSize": { "width": 3024, "height": 1898 },
  "preprocess": { "sampledFrames": 0, "modelCalls": 0, "failedBatches": [] },
  "segments": [
    { "id": "seg-example", "start": 214, "end": 267.5,
      "origin": "external", "concepts": [], "reviewStatus": "candidate" }
  ],
  "dropped": []
}
```

示例不是合法现有响应，也不是运行数据。片段时间范围、每个可绘制对象的**具体帧时间及源尺寸**、来源、候选/人工确认状态、冲突与失败都需冻结；片段范围不能随意代替单帧对齐身份。置信度只有供应商提供且语义明确时记录，不编造值；`validated` 只能由本地校验产生，候选自报 `validated: true` 不可作为门禁。

转换边界必须显式：现有 `CurveResult` 只接受已登记的抛物线形状；005 `SceneResult` 只接受其直角三角形条件。合法且可表达的对象可通过受控适配器再次校验后进入对应层。其他形状应拒绝或先批准新契约与渲染适配，**不能保证所有 `shape` 都能转换为现有 `CurveResult` 而无需改绘制层**。原则 VI 约束同一既有交接面，不禁止获准的独立时间轴文档。

| 端点候选 | 用途 | 尚需冻结 |
| --- | --- | --- |
| `POST /preprocess` | 一批帧产生候选片段 | 版本、job/batch/video 身份、课程说明、时间/尺寸、来源、状态与错误、帧数/载荷/预算/成本 |
| `POST /preprocess/merge` | 可选的跨批合并 | 是否确需服务端；本地确定性合并、冲突规则与取消优先评估 |

端点尚不存在，也未获实施批准。8MiB 批量请求上限只是候选，不由 8–16 帧自动保证；现有 `/read` 服务路由上限为 10MiB，当前帧客户端与 005 几何各限 4MiB，不混为同一限制。未来 spec 编号和目录由批准的工作决定，本次不建立 `006`。

### 3.6 L3-① 粒子呈现

粒子位置应来自已确认的数学对象与确定性采样；它可提供同一对象的另一种画法。模型自由生成点云若被展示为事实，会绕过门禁。原生 WebGL 本身也不证明来源诚实、几何正确或获得实施批准。

| 方案 | 可取之处 | 需验证的成本 |
| --- | --- | --- |
| 原生 WebGL | 不增加第三方运行时库，资源可本地打包 | shader、资源释放、context loss、采样与设备适配 |
| 固定版本 Three.js | 可复用 renderer/资源管理 | 产品依赖变更、版本/来源/完整性/许可、离线包体与性能；展示站现有文件不能自动移植 |
| Canvas 2D | 可作为小规模原型或降级 | 在冻结设备上的粒子数与帧率，不能预先断言几千粒子一定掉帧 |

P0 继续优先原生 SVG。未来新表示层先记录技术选择；新增依赖遵循 AGENTS 和精确版本规则，影响宪法边界时再修订。`script-src 'self'` 要求扩展执行资源本地化，并不能消除本地第三方库的供应链风险。

4,000 桌面粒子、1,500 较弱设备粒子、30fps 可作为**未测的原型目标**，不是兼容承诺。资源预算至少覆盖首次/缓存初始化、帧率分布、内存或显存可观察限制、设备下限和 SVG 降级。减少动效、隐藏页面、退出及 WebGL context loss 均须有行为和释放规则。shader/可执行代码不得远程加载；纹理等数据资源按 CSP、来源与隐私规则分别决定。上述指标与 P0 的 1500ms/100ms 分开。

### 3.7 L3-② 分龄解析

同一份已确认题目与确定性计算结果，可试验不同措辞、细节密度和类比。**原则 VII 的「不得生成 HTML、幻灯片、测验、语音或第二种曲线」限定于 003 预读路径**，不能泛化为全部产品永久禁令：005 已授权一道本地确定性理解题。新分龄功能仍须明确范围与验收，不能借解释模板增加未批准的生成路径。

在 005 动作中加入 `depth` 是契约变更草案，当前白名单不接受该字段；可先评估 UI/本地模板选项，若改变动作响应则须修订 Schema 与两侧校验。

```js
// 草案，不是当前可发送的动作。
explain_change = {
  type: 'explain_change',
  depth: 'concrete' | 'standard' | 'formal'
}
```

数值取自实际执行结果，内容需核对与同一对象一致。年龄不必机械映射理解深度，可让用户选择表达方式；首版可只研究 standard/concrete。数学框架切换会增加内容体系与专家核对，宜后置。表达偏好或本次答题改善不能证明长期学习提升，延迟测试另行设计。

## 第四部分　建议推进顺序

### 4.1 先补已批准范围的证据

1. 指定正式素材、源帧、曲线参数与当前验证入口；核对本地视频和真实网站的承诺。
2. 分别补 001 T030/T038、003 SC-003/004/005、当前帧真实模型与 005 的独立验收，不混用计时或对齐证据。
3. 对真实片段建立成功/拒绝/失败表，包含模糊、遮挡、无图形、不支持和取消。样本数与选取规则先写清，不从少量视频推断所有视频准确率。
4. 用具体复现支持生命周期、资源读取或 reader 修复，并更新受影响说明。静态检查和替身回归只报告其实际覆盖。

### 4.2 再选择下一层

- 若目标是更多可识别数学对象，选一种新增形状做 L1，再为该类型补真实识别；不必一次承诺「全几何」。
- 若目标是观看前标注概念，先限制 L2 输出类型与素材范围，完成新准入文件后再实施。
- 若目标是表现力或解释体验，L3 可从已有确认对象独立试验；不得把本地原型计入模型理解或学习效果。
- 若目标是真实网站或真 3D，分别设支持边界和研究验收，不能用展示站背景或 2D 粒子视角代替。

交付窗口较短时优先已有验收与必要修复；较长时按试验结果逐项扩大。时间充裕也不自动批准全部层级，候选方向仍遵循原则 X。

### 4.3 保留三条纪律

1. **来源可追溯。** 外层 origin、对象来源、人工校对和失败片段分别记录；不把预设或替身计入自动识别。
2. **确定性门禁。** 模型只产候选，可表达形状、参数、时间身份与上下文都通过对应校验；未支持对象拒绝。
3. **各层独立验收。** 新渲染成功不能证明视频理解，新解释成功不能证明长期学习，新模式不能反向覆盖旧验收。

### 4.4 建议后置的方向

| 项 | 后置理由 |
| --- | --- |
| 从视频重建真实 3D | 需要独立几何、识别和真值体系；当前 2D 契约不能表达 |
| 按数学框架切换整套分龄内容 | 内容与专家验证工作尚未定义 |
| 覆盖未验证在线视频的预处理 | 访问、素材权利、平台约束与供应商数据边界尚未明确 |
| 与决策/实现/验收无关的重复分析文档 | 优先更新唯一当前入口，保留必要历史与治理记录 |
