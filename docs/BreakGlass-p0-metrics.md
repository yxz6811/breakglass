# P0 评测指标

日期：2026-10-02。范围只包括宪法里的 P0：扩展内演示页上的一条预先准备抛物线。识别任意视频和本地 Python 不在本表。

环境记在每条手工记录上：Google Chrome 的版本号、Linux 虚拟机的发行版与配置、是否热缓存。缺这些字段的耗时和偏差记录不算通过。

通过规则：自动测试用 `node --test`。手工项必须在 Chrome 里做完并写入 `docs/BreakGlass-frontend-validation.md`。未运行的项目保持未通过。

## 1. 主路径

| 编号 | 通过标准 | 怎么判 | 现状 |
| --- | --- | --- | --- |
| M1 | 从暂停的目标帧起，90 秒内完成唤醒、改动一个参数、重置、退出，全程断网 | 计时一次 | 操作者确认 Chrome 主路径无问题。版本号未记 |
| M2 | 未暂停，或不在目标时间 ±0.2 秒，破壁入口不可用，画面上不留曲线 | 播放中和拖离目标时间各试一次 | 自动测试覆盖；手工随 M1 确认 |
| M3 | 按钮和 Alt+B 都能唤醒。已有覆盖层时不再挂第二层 | 两种入口各一次 | 同上 |
| M4 | 拖动时数字、滑块和曲线一起变，参数停在素材的 min 与 max 内 | 拖到两端再拖出界外 | 自动测试覆盖钳制；手工随 M1 确认 |
| M5 | 重置回到本次初值，交互层仍在。Esc、退出按钮、点击交互层外部都能退出，视频保持暂停 | 三条退出路径各一次 | 同上 |
| M6 | 连续 10 次准备结果唤醒，10 次都能看到「预先准备的示例」或同等含义，0 次出现「识别成功」 | 数来源文案 | 自动测试禁止「识别成功」字样。10 次人工计数未记 |

## 2. 超时、失败和取消

配置演练时改 `externalAttempt`，结束后改回 `off`。热缓存：扩展和预制 JSON 已经加载过。每种需要计时的场景至少 20 次，报告 P50 和 P95。

计时只含一段：判定超时，到第一个可见 SVG 帧。打开扩展、视频首帧、网络等待、Pyodide 初始化不计入。

| 编号 | 通过标准 | 怎么判 | 现状 |
| --- | --- | --- | --- |
| M7 | `hang` 满 1.5 秒后不用再点击就出现匹配曲线。来源持续为「预先准备的示例 · 超时回退」，并说明因等待超过 1.5 秒。更晚的结果不改变曲线 | 看页面，并把迟到结果放行 | 自动测试通过。Chrome 手工未记 |
| M8 | 热缓存下，M7 的「判定超时 → 首个 SVG 帧」P95 ≤ 100ms。同时写下 P50、起点、终点、浏览器版本、机器、热缓存 | `window.__breakglassLatency.summary()`，至少 20 次 | 未测 |
| M9 | `invalid`，以及没有匹配预制：不画曲线，不显示成功，两步内可重试或退出，播放器仍能操作 | 各走一遍 | 自动测试通过。Chrome 手工未记 |
| M10 | 等待中取消或按 Esc，回到暂停。之后的结果不能打开覆盖层 | 在 1.5 秒内取消，再等过超时点 | 自动测试通过。Chrome 手工未记 |
| M11 | 视频打不开或没有视频：不挂曲线，入口不可用或有说明，播放器不被改写 | 拿掉视频再打开演示页 | 页面有缺失说明。Chrome 手工未单列 |
| M12 | 连续 5 次退出再唤醒，或换帧再唤醒，旧结果不覆盖当前画面 | 数覆盖层和请求 | 自动测试通过。Chrome 手工未记 |

## 3. 画幅

同一目标帧、同一条曲线。偏差 = 采样点上 `|实测 SVG 点 − 期望画面点|` 的最大值 ÷ `min(内容区宽, 内容区高)`。只比较视频内容区，黑边不参与。采样含顶点、定义域两端和等距 9 点。

| 编号 | 通过标准 | 怎么判 | 现状 |
| --- | --- | --- | --- |
| M13 | 16:9、4:3、竖屏、带黑边，每种偏差 ≤ 2% | 读 `window.__breakglassAlignment`，记下内容矩形、短边像素、最大偏差像素和比例 | 自动测试覆盖算法。Chrome 四种框的比例未记 |
| M14 | 交互出现后改变一次窗口大小，偏差仍 ≤ 2%。全屏或设备像素比变化后重算 | 各做一次并记录 | 自动测试覆盖重算触发。实测比例未记 |
| M15 | 播放或离开目标时间后，覆盖层消失 | 四种框里任选一种复查 | 自动测试通过。Chrome 手工未单列 |

## 4. 不计入 P0

以下失败不否定 P0，也不记成 P0 已做：

- 任意函数视频的一键识别
- 单帧上传和感知代理
- 扩展内 Python / Pyodide
- 手持晃动、强透视、未验证网站
- 账号、历史记录、云同步

## 5. 完成线

M1–M6 的主路径已有操作者确认。M7–M15 的自动测试已通过的，仍要有 Chrome 记录才算该项手工通过。M8、M13、M14 没有数字就不能勾。十五项都通过，P0 评测才完成。
