# BreakGlass 前后端职责边界

> 状态：仓库开发约定
>
> 本文汇总 `AGENTS.md`、`docs/BreakGlass-constitution.md`、前端分析与执行计划，以及 `specs/001-insitu-parabola/` 下的规格、契约和验收文档。它用于在需求拆解、实现、联调和代码审查时判断工作是否属于本仓库。

## 1. 结论

`yxz6811/breakglass` 当前是前端项目。P0 的交付物是一个 Chrome MV3 扩展和扩展内的离线演示页：使用 HTML5 Video API 播放受控视频，用原生 SVG 显示可调节的抛物线，并用随扩展打包的预制 JSON 完成可重复演示。

本仓库不新增业务后端、数据库、账号系统、云端 Python 执行容器或自建识别服务。扩展没有 Node.js 运行时依赖。根据前端 Constitution 1.5.0 及 Spec Constitution 1.7.0，既有 `breakglass-reader/` 是开播前阅读的独立例外：源码在仓库、不进入扩展包、不部署云端后台；全仓库测试与该服务需要 Node.js ≥22.9。

Python/Pyodide、本地 Web Worker 和真实视觉识别属于独立 P1 vertical slice。它们只有在单独的开关、契约、安全预算和验收证据齐备后才能进入实现，不得阻塞或抬高 P0 的验收门槛。

Spec Kit 的治理记忆已经记录了开播前阅读的窄例外。用户填写阅读地址后，页面仅向该地址发送最多 8 张缩小的帧及相关元数据，既有 reader 根据环境配置调用模型。密钥不进入浏览器或扩展；该例外不授权新增通用后台、数据库或云端部署，也不代表任意视频阅读已验收。

## 2. 责任分工

| 能力 | 本仓库前端负责 | 外部后端或平台负责 | 当前状态 |
| --- | --- | --- | --- |
| 页面与扩展体验 | MV3 manifest、演示页、视频控制、SVG overlay、参数控件、加载/错误/取消/退出状态、键盘和可访问性 | 无 | P0 前端范围 |
| 视频与坐标 | 通过标准 HTML5 Video API 读取 `currentTime`、`videoWidth`、`videoHeight` 和显示矩形；处理 `object-fit`、`object-position`、黑边和窗口变化 | 提供可用的视频素材、目标时间和坐标说明 | P0 依赖素材 |
| 曲线结果 | 读取预制 JSON；执行 JSON Schema、白名单求值器、有限值、范围、视频标识、时间和请求编号校验；绘制通过校验的结果 | 若未来提供识别结果，保证按已确认契约返回候选结构化数据 | P0 使用 `preset` |
| 本地 Mock 与保底 | 每个交互节点读取 `enableLocalMock`；匹配预热结果时进入本地演示；超时后显示“本地预制/超时回退”和原因；无匹配结果时显示错误、重试或退出 | 不提供 Mock 服务，不接管前端状态 | P0 静态 JSON |
| 真实视觉识别 | 未来仅实现已确认接口的请求适配、取消、超时、响应映射和错误展示；不得在浏览器代码中放置服务端密钥 | 由外部服务提供识别、鉴权、限流、模型运行、数据保留和服务端最终校验 | P1 外部依赖，当前未接入 |
| Python/Pyodide | 若单独立项，负责本地 Worker 生命周期、输入输出限制、白名单包、超时 terminate 和可见状态 | 不建设远程 Python 容器，不提供任意代码执行后端 | P1 实验，当前未实现 |
| 数据持久化与账号 | 仅保存必要的临时 UI 状态；不把浏览器缓存当权威数据 | 账号、权限、数据库、历史记录、云端同步和服务端业务规则 | 当前不做 |
| 部署与运维 | 扩展资源组织、开发加载说明、前端测试和演示记录 | 生产 API、域名、证书、数据库、监控、部署和运维 | 当前无自建服务 |

## 3. 允许进入前端仓库的内容

以下内容属于前端范围，可以在不新增后端的前提下实现：

- Chrome MV3 manifest、扩展页、service worker、content script 和标准消息通信；是否注入页面仍受已验证域名、页面结构和权限约束。
- 使用标准 `<video>` API 的播放、暂停、定位、源尺寸读取和事件监听。
- 视频上方独立的 SVG/HTML overlay、曲线求值、参数拖动、重置、ESC 退出和窗口变化后的坐标重算。
- 随扩展打包的静态视频、预制 `CurveResult` JSON、运行配置和明确标识的开发/演示 Mock。
- API 适配层、请求取消、超时、响应映射和错误提示，前提是外部接口契约已经书面确认。
- Node.js 的 `node --test` 测试及不提供业务接口的前端开发工具；既有 `breakglass-reader/` 按 Constitution 的独立例外维护。

## 4. 禁止在本仓库新增的内容

除 Constitution 已明确批准的既有独立 reader 外，以下新增变更越过当前职责边界，不能为了补齐演示流程而直接添加：

- FastAPI、Express、Node.js HTTP 服务、Docker 服务、云端 Python 执行容器或独立 BFF。
- 数据库、表结构、迁移、服务端持久化、历史记录服务、账号注册/登录和服务端鉴权。
- 视觉模型服务、帧上传代理、模型密钥中转或任何需要服务端保密凭据的实现。
- 用 LLM 预测代码输出、模拟循环/递归结果，或将模型回答作为执行结果。
- 任意网站、跨域 iframe、Shadow DOM、DRM 或未验证播放器的通用注入承诺。
- 与核心演示无关的 SaaS 功能，例如云端同步、点赞分享、多语言和多语言代码执行平台。

“前端开发服务器”“本地静态服务器”或测试命令不属于上述禁止项，只要它们不承载业务接口、不保存业务数据，也不成为演示的隐含后端依赖。

## 5. 接口缺失时的处理

接口缺失不等于在本仓库内补建一个服务。处理顺序固定为：

1. 先完成不依赖接口的页面、状态、预制结果、坐标和错误路径。
2. 在 `docs/` 或对应 `specs/` 契约中记录待确认的调用方、方法、地址、请求字段、响应字段、鉴权、超时、错误语义和数据保留要求。
3. 使用与契约一致、明确标注的静态 Mock 验证前端流程；Mock 不得被描述为真实链路已打通。
4. 外部接口确认后，只在前端实现请求适配和展示状态，并保留确定性结果校验。
5. 任何需要新增后端、数据库、服务端密钥或改变数据流的方案，必须先作为范围变更记录并重新审查 Constitution、Spec、Plan 和 Tasks。

## 6. 数据来源和状态标识

前端界面与文档必须区分以下状态：

| 状态 | 可以声称的内容 | 不可以声称的内容 |
| --- | --- | --- |
| `preset` | 使用与当前视频、时间和帧尺寸匹配的预制结果 | 已完成真实识别 |
| `preset` + `timeout` | 外部等待超时后使用预热的本地结果，并显示原因 | 外部服务成功返回 |
| `vision` + `evidence: packaged-sample`（001 之后的识别适配切片） | 这是**随扩展打包的识别样例**，走与预制结果同一套校验，界面全程显示「识别结果」与「尚未接通外部识别」 | 外部接口已返回、单帧已离开浏览器、识别已接通 |
| `vision`（未来真实接口） | 外部接口按已确认契约返回并通过确定性校验的结果 | 结果天然正确或模型没有幻觉 |
| `mock`/fixture | 前端状态、几何和交互验证数据 | 已对齐正式视频或已完成产品验收 |
| `error`/`cancelled` | 失败或取消已被用户看见，提供重试/退出路径 | 静默转成成功结果 |

生产构建不得意外开启 `enableLocalMock`。P0 主路径可以使用 `enableLocalMock: true` 的离线演示配置，但来源文案必须从曲线出现到退出持续可见。

## 7. P0 和 P1 的边界

### P0 当前可以合并

- 单个录屏或固定机位数学抛物线场景。
- 扩展内演示页、播放/暂停/定位、预制曲线、参数调整、重置、退出和来源标识。
- 原始帧、数学坐标和页面显示坐标之间的确定性映射。
- 结果校验、请求编号防竞态、资源失败和可恢复的本地演示路径。

### P1 必须另行立项

- 真实视觉识别、单帧上传和远程接口。
- Python/Pyodide、WASM、Worker 以及任意代码执行。
- 其他数学对象、多场景、任意网站注入或动态实拍视频。

P1 立项至少要同时记录精确依赖版本、资源来源与完整性校验、MV3 CSP 和资源路径、Worker watchdog、输入/输出/内存预算、包白名单、网络隔离、取消行为、数据隐私和独立验收证据。

## 8. 当前规格的任务边界

`specs/001-insitu-parabola/ownership.md` 对 18 个任务作了明确拆分：前端 10 项，结果契约/校验/预制数据 8 项。这里的“后端”不是服务端工程，而是决定哪份结果可以进入交互层的确定性规则；对应代码仍位于 `extension/`、`tests/` 和 `specs/001-insitu-parabola/contracts/`。

| 任务类别 | 负责内容 | 当前规则 |
| --- | --- | --- |
| 前端任务 | MV3 表面、演示页、视频控制、内容矩形、SVG 绘制、参数交互、手工浏览器验收 | 可以在本仓库实现；不新增 `backend/` |
| 结果规则任务 | `CurveResult` 校验、白名单求值器、运行配置、预制 JSON、会话是否允许绘制 | 仍是前端工程内的纯函数和静态资源，不是 API 服务 |
| 后端/识别任务 | 真实识别、单帧上传、感知代理 | 当前不派发；需先完成上传决定、Constitution 修订和独立 P1 立项 |

当前承诺仍是扩展自带演示页上的单场景抛物线。2026-10-02 操作者确认 P0 主路径的 Chrome 手工验收通过，见 `docs/BreakGlass-frontend-validation.md`。9 秒演示视频已提交。故事 2、故事 3 已有自动测试；真实呈现耗时和四画幅实测比例仍需验收。独立阅读服务已有源码和模型替身测试，真实模型与另一支视频的阅读仍未通过验收。

### 识别适配切片（`specs/002-vision-result-adapter/`）的边界

该切片新增默认关闭的 `visionAdapter` 开关（只允许 `off` / `fixture`），打开且外部演练为 `off` 时读取**随扩展打包**的识别样例，并用同一个 `validateCurveResult` 放行。边界仍然成立：

- `source: "vision"` 在本切片**只**表示 `evidence: "packaged-sample"` 的打包样例；它不表示外部接口已返回，不表示单帧已离开浏览器，也不表示识别服务已接通。
- 不新增上传地址、主机权限、内容脚本、远程脚本或后端进程；样例读取路径只有扩展包内的 `extension/assets/vision/fixture-parabola.json`。
- 此处描述的是 002 打包识别样例，不上传画面。后续 003 开播前阅读按 Constitution 1.7.0 的独立例外发送稀疏帧，不能用其例外声称 002 已接通真实识别。
- 识别适配的开关、样例、校验与会话规则属于本仓库的「结果规则」侧；页面只消费 `createWake` 的 `onChange` 状态并显示来源文案。
- `.specify/memory/constitution.md` 已由 1.3.0 修订为 1.4.0：默认关闭时 `interactive` 的 `result.source` 仍只能是 `preset`，只有 `visionAdapter: "fixture"` + `externalAttempt: "off"` 时才允许 `source: "vision"` + `fallback: null` + `evidence: "packaged-sample"`。

## 9. 合并前的边界检查

每个涉及接口、执行或数据的变更，在合并前回答以下问题：

- 改动是否只影响浏览器端页面、扩展资源、状态或适配层？
- 是否新增了服务进程、数据库、服务端密钥、业务 API 或持久化责任？
- 所有外部依赖是否有明确的 owner、契约、状态和失败语义？
- 静态 Mock、夹具、真实结果和超时回退是否有不同的来源标识？
- 结果是否在进入执行/绘图前通过 Schema、语法、范围和当前帧匹配校验？
- 是否更新了受影响的 Spec/Plan/Tasks，并记录了未验证范围？

若答案显示变更越过前端边界，先暂停实现并登记范围变更；不得通过新增一个“临时后端”或静默 Mock 来绕过审查。
