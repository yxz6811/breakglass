## 1. 交付目标

完成一个可稳定演示的单场景前端工作台：加载团队提供的录屏或固定机位数学抛物线视频，播放或暂停到指定位置，进入“破壁”状态，显示与当前画面对齐的可交互 SVG 曲线和参数控制，拖动后实时更新，支持重置、退出、取消、超时和明确标记的本地预制保底。

交付口径只覆盖当前资料中的数学抛物线 MVP。任意视频、完整代码沙盒、多场景并行、通用视觉识别和“纯本地”能力都需要单独确认与验证；不新增云端 Python 容器、数据库、账号体系或其他后端。

## 3. 推荐的实现边界

### 3.1 一个工作台，五个状态

| 资料编号 | 前端状态 | 主要内容 |
| --- | --- | --- |
| P-01 | 工作台初始 / 播放 | 视频、控制条、破壁入口、来源说明 |
| P-02 | 暂停待破壁 | 当前帧、定位结果、破壁按钮 |
| P-03 | 识别中 | 加载反馈、取消或返回、等待说明 |
| P-04 | 交互完成 | SVG 曲线、参数滑块、数值、重置 |
| P-05 | 错误 / 退出 | 错误反馈、预制演示入口、返回暂停状态 |

这五项建议实现为同一页面的状态变化。这样可以保持视频舞台、控制条和交互层的一致性，也方便现场快速恢复。

### 3.2 前端状态

```text
loading
playing
paused
recognizing
interactive-real
interactive-preset
recognition-error
asset-error
```

必须保持以下状态约束：

- 视频播放时不显示仍绑定在旧帧上的交互曲线。
- 进入识别时锁定当前视频标识和时间位置。
- 切帧、退出、取消或重新识别后，旧结果不能覆盖当前界面。
- 真实识别和预制结果使用同一套曲线渲染和参数控件。
- 重置恢复当前结果的初始参数；退出移除交互层并回到暂停状态。
- 预制模式持续显示数据来源，避免用户把预制结果误认为识别成功。

## 5. 建议的数据模型

下面是前端适配层建议结构，不是已确认的后端 JSON。实际接口确认后再映射。

```ts
type CurveResult = {
  source: 'preset' | 'vision'
  requestId: string
  videoId: string
  time: number
  frameSize: { width: number; height: number }
  region: { x: number; y: number; width: number; height: number }
  curve: {
    type: 'parabola'
    equation: 'vertex'
    a: number
    h: number
    k: number
  }
  domain: { min: number; max: number }
  ranges: {
    a: { min: number; max: number; step: number }
    h: { min: number; max: number; step: number }
    k: { min: number; max: number; step: number }
  }
  confidence?: number
}
```

进入交互层前应检查：

- `requestId` 与当前请求一致。
- `videoId` 和 `time` 与当前暂停位置匹配。
- 所有尺寸和参数都是有限数值。
- `region` 位于帧范围内或有明确裁剪规则。
- `a`、`h`、`k` 位于允许范围。
- `source` 与界面提示一致。

## 6. 坐标实现要求

实现前先固定三套坐标：

1. 原始帧像素坐标：用于表示识别区域。
2. 数学坐标：用于计算抛物线。
3. 页面显示坐标：用于 SVG 覆盖层和鼠标触控。

页面缩放、视频留白、窗口尺寸变化和设备像素比都可能影响显示坐标。SVG 覆盖层应与视频的实际内容区域绑定，不直接使用外层容器的宽高作为唯一换算依据。

首版只验收已验证的页面结构和域名。跨域 iframe、Shadow DOM、DRM 和无法访问的媒体不纳入支持范围；扩展的 MV3 注入与消息通信不等于可以绕过浏览器同源限制。

建议首版采用顶点式 `y = a(x - h)^2 + k`：

- `a` 控制开口方向和宽窄。
- `h`、`k` 控制顶点位置。
- 滑块负责参数输入，顶点拖动可作为同一参数的直接操作。
- 参数范围、步长和坐标轴方向必须从最终视频和数学场景确认。

## 7. 失败与保底路径

| 情况 | 前端行为 | 演示要求 |
| --- | --- | --- |
| 视频加载失败 | 展示可理解错误，提供预制入口 | 预制资产必须可用 |
| 无法定位目标帧 | 跳转到已知预设帧并提示 | 预设时间和帧需提前验证 |
| 识别超时 | 停止等待，允许预制演示 | 不静默伪装为识别成功 |
| 识别失败 | 显示失败原因或通用提示，提供预制交互 | 预制结果需仍可拖动和重置 |
| 用户取消 | 清理请求状态并回到暂停 | 不能留下半透明加载层 |
| 窗口缩放 | 重新计算显示映射 | 曲线仍和视频目标对齐 |
| 旧请求返回 | 丢弃结果 | 不覆盖当前帧或当前参数 |

每一个交互节点都读取静态 JSON 中的 `enableLocalMock`。真实请求超过 1.5 秒时自动取消或标记超时并切换预热缓存；这个切换不要求用户再次点击，但必须显示来源和回退原因。回退前校验 `requestId`、视频标识和帧位置，迟到结果直接丢弃。生产构建不得意外开启 Mock。

## 8. 开工前的六个决策

这些决策会直接改变实现和验收，建议先在团队文档中确认：

1. MVP 是否正式锁定为单个数学抛物线视频。
2. 真实识别是 P0 交付门槛，还是标识清楚的增强功能。
3. 目标视频、目标帧、公式、初值、参数范围和坐标区域。
4. 重置是否保留交互层，退出后是否保持暂停。
5. 现场识别等待上限和保底切换方式。
6. 目标浏览器、屏幕比例、网络条件和是否需要触屏。

若启用 P1 Python/Pyodide，还必须单独确认精确版本、资源完整性校验、MV3 CSP 与本地资源路径、2 秒 Worker watchdog、输入/输出上限、内存可测性、包白名单、网络隔离和取消后的 terminate 行为。

## 9. 前四小时执行顺序

如果团队确认以上决策，前端可以按下面顺序推进：

1. 检查已有仓库、依赖、锁文件和启动脚本；没有工程时再选择技术栈。
2. 放入已确认的视频和预制结果，先让页面可以稳定打开。
3. 完成工作台布局和控制条，不等待真实识别接口。
4. 用预制参数完成 SVG 曲线、滑块、数字和重置。
5. 在目标帧上验证视频与 SVG 映射，再处理窗口变化。
6. 补齐加载、错误、取消、ESC 和预制入口。
7. 记录真实识别接口需要的字段，等外部契约确认后接入。
